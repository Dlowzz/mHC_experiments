# mHC branch write-back 梯度诊断（XL / mhc, iter 80000）

数据：`out-owt-xl-mhc-bs6-80000step/ckpt_last.pt`，4 batch × 2 seq × 1024 token（8192 token），
bf16 autocast（与训练一致）+ 1 个 fp32 batch 做恒等式校验。未训练、未改模型逻辑。
脚本 `diagnostics/diagnose_beta_writeback.py`，全量数据 `beta_writeback_xl_mhc.json` /
按层 attention·FFN 分行的 `beta_writeback_xl_mhc.csv`。

## 结论先说

**梯度聚合本身没有问题，你怀疑的方向不成立。** 恒等式
`dL/df = Σ_i β_i g_i` 在全部 56 个 hc 站点上 fp32 相对误差 **0.000e+00**，是精确的线性组合。
而且在出问题的那一层，聚合是**衰减**而不是放大的：L00.attn 的
`||dL/df|| / mean_i||g_i|| = 0.25`。

异常首次出现在 **β 这一级**，起因是**前向的尺度失配**，不是反向的聚合：

```
y_i  ──→  f  ──→  β_i  ──→  z_i  ──→ (β_static, α, W_post)
正常      衰减    ★爆炸    被饱和压掉    L00 高出 2~3 个量级
                (2.3e2)   (×1/385)
```

## 1. branch 梯度聚合：β 大 or 方向一致？都不是主因

把放大倍数精确分解成两个乘性因子（n=4，`amp = √n · coherence · β_w`，
`coherence` = 1 表示各 `β_i g_i` 正交、2 表示完全平行）：

- 深度平均 `coherence` 1.12 → 1.67，`cos(g_i, g_j)` 逐层单调上升 **+0.55 → +0.91**。
  流间梯度方向确实越来越一致，但上限只有 √n·2 = 4 倍。
- `β_w` 分化极大：attention 站点 0.14 → 0.05（在关闭），FFN 站点 0.26 → 0.89（在打开）。

实测 `amp` 最大只有 **3.3**（L23.mlp），attention 站点普遍 **0.06~0.8**。
所以 FFN 站点是"β 大 + 方向一致"两者共同作用（各贡献约 2 倍），
但绝对量级都很小；attention 站点方向最一致却因 β≈0 而完全传不出去。
**没有任何站点靠聚合放大出量级问题。**

关键反证：L00.attn 的 `cos` 是全网**最低**的（off-diag 均值 +0.285，最小 0.028），
偏偏它的梯度最大。方向一致性无法解释 layer-0 的异常。

## 2. 真正的爆点：L00.attn 的 `dL/dβ`

`dL/dβ_norm` 的深度分布（attn / mlp）：

- L00: **2.31e+02** / **3.90e+01**
- L01: 5.03e-01 / 7.53e-02
- L03~L27: 3e-03 ~ 1.4e-01

L00.attn 比第二名高 **3 个量级**，与"98% 梯度集中在 wte+wpe+layer0"完全对齐。

原因在前向：`dL/dβ_i = ⟨g_i, f⟩`，而 layer 0 的 `||f||` 远大于 `||r_i||`。
L00.attn 逐流（home stream = 0）：

- `β_i`      = [0.0007, 0.0012, **0.347**, 0.0000]
- `||β_i f||` = [93.9, 70.5, **1.264e+04**, 0.38]
- `||r_i||`   = [39.2, 32.3, 29.3, 37.5]
- `写入/残差` = [2.4, 2.2, **431.6**, 0.01]

即 stream 2 收到的写入是它自身残差的 **431 倍**；反推 `||f|| ≈ 3.6e4`，
是 layer-0 残差尺度（~30–40）的约 **10³ 倍**。对比中后层 `写入/残差` 只有 0.02~0.35。
这是典型的 massive-activation：layer 0 的 attention 输出压根不在残差的量级上。

## 3. sigmoid 饱和：门想关但关不动

`sat = ||dL/dz|| / ||dL/dβ||`（即有效 `dβ/dz`，理论上限 0.5，在 β=1 取到）：

- **L00.attn 0.0013**（比 β=1 处钝 385 倍），L00.mlp 0.0082
- attention L21–27 平均 0.035（`β<0.1` 的 token 占比 0.82，L24.attn 高达 0.996）
- FFN L14–27 平均 0.24–0.26（`β>1.9` 占比 0.12–0.19，`β_max` 精确等于 2.000）

**两端都饱和，且方向按站点类型分裂**：attention 门被压到 0（z 均值 −2.9 ~ −7.1），
FFN 门被推向 2（z 均值 ≈ 0 ~ +0.04，z_max 达 +16）。

你猜的"branch 收到越来越大的梯度，但 β gate 因饱和越来越难调整"在 L00.attn 上完全成立：
`dL/dβ = 2.3e2` 是全网最大，`dL/dz` 只剩 3.0e-1；门已经把 z 压到 −14（见下），
仍然只能以极慢的速度移动，而 `dL/dW_post = 4.68`、`dL/dα = −4.03` 每步照旧全力冲击门参数
——这才是总 grad norm 飘的直接来源。

## 4. 是谁在推 β：动态分支，不是 β_static

把 `z_i = β_static_i + α·(normed @ W_post)_i` 按 token 均值拆开，L00.attn：

- `β_static` = [−2.14, −1.46, **+0.62**, −1.99]（初始为 [+1, −1, −1, −1]）
- `z_dyn`    = [−12.05, −6.77, −2.48, −13.41]

动态项比静态项大 **5~6 倍**，z 总量 −14 ~ −1.9。跨 ckpt 看（56 站点均值）：

- `α = h_post_scale`：init 0.0100 → 0.1312 (iter 28500) → **0.1603** (79000) → 0.1605 (80000)，
  即 **16 倍**于初始，单站点最大 0.318
- `||W_post||_F`：init 0 → 5.102 → **5.325**，单站点最大 8.455 → **12.020**（+42%）
- `β_static` 均值：−0.5000 (init) → −0.5693 → **−0.5955**

**`β_static` 是往负方向漂的，不是正方向** ——你这条假设不成立。它在把门往关的方向推
（L00.attn 的 home 流从 +1.0 掉到 +0.62，其余三流从 −1 掉到 −1.46~−2.15），
只是幅度小、且被饱和拖慢。真正把 z 撑起来（FFN）或压下去（attn）的是 `α` 和 `W_post`：
α 涨 16 倍、W_post 从 0 长到 5.3，token 相关项已经完全主导 z。

79000 → 80000 这 1000 步几乎冻结（α 0.1603→0.1605，||W_post|| 5.325→5.319），
符合此时 lr 已在 min_lr = 2e-5。

## 判定：异常首次出现的层级

**β_i**（由前向 `||f||/||r||` ≈ 10³ 的尺度失配产生），不是 `y_i`、不是 `f`、不是聚合方式。
`z_i` 及其下游（α、W_post）是被这个爆点带大的，同时 sigmoid 饱和让 `z` 这一级失去了纠正能力，
形成"写入过大 → 门想关 → 关不动 → 门参数持续吃大梯度"的闭环。
`β_static` 参与得很少，且方向与假设相反。

按这个结论，值得优先试的方向不是改聚合，而是压掉 layer-0 的 `||f||/||r||`：
例如给 branch 输出加一个与残差同量级的归一化，或把 β 的参数化换成不在两端饱和的形式
（softplus / 有界线性），让门在 β→0 与 β→2 附近仍保留梯度。

## 口径与局限

- 8192 token 的单点采样。逐 token 均值类指标稳定，尾部占比（`β>1.9`、`β<0.1`）方差较大。
- `r_i` 取的是 `width_connection` 经 Sinkhorn 混合后的残差（`mix_h[..., 1:, :]`），
  不是进入 block 的原始残差；`x W_post` 的 `x` 是全流拼接后的 RMSNorm 结果 `normed`。
- `α` 对应 `h_post_scale`（H_post 侧），与 H_res 侧的 `pre_branch_scale` / `residual_scale` 无关。
- `dL/dz` 由 `dL/dβ · β(2−β)/2` 精确得到，`z = logit(β/2)`，无需额外插桩。
- iter 28500 那个 ckpt 属于另一次 run（bs4、不同 lr schedule），只用于看聚合量的趋势；
  它的 per-stream home 流与 bs6 run 不同，逐流数值不可跨 run 对比。
